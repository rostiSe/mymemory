# Workspace packages and build (`@mymemory/shared`)

How the mobile app consumes the internal **shared** package, why **`dist/`** is the single entrypoint, and how **CI / local dev** should produce it.

## Package surface

`packages/shared/package.json` exposes:

- **`@mymemory/shared`** → compiled `dist/index.js` + `dist/index.d.ts`
- **`@mymemory/shared/contracts`** → `dist/contracts/*`

Source lives under `packages/shared/src`. **Do not commit `dist/`** (or generic `build/` outputs) — they are generated by `tsc` locally or in the pipeline.

## Why `exports` point at `dist/` only

- **One resolution path** for Metro, the server (`module: NodeNext`), and the IDE.
- Avoids split **`react-native` → `src`** vs **`import` → `dist`** rules that previously caused missing modules and mismatched extension resolution.
- Runtime loads plain ESM JS; types align with emitted `.d.ts`.

## TypeScript ESM detail (NodeNext)

Internal relative imports in shared **source** use **`.js` specifiers** (e.g. `./entry.contract.js`) so emitted declaration files re-export with valid specifiers for Node ESM resolution. Without that, consumers using `NodeNext` can see “has no exported member” even though source looks correct.

## When `dist/` is produced

| Trigger | What runs |
|---------|-----------|
| **`pnpm install`** | `prepare` on `@mymemory/shared` runs `pnpm run build` (`tsc`) |
| **`pnpm dev`** (root) | Turbo `dev` has `dependsOn: ["^build"]` — dependency packages build first |
| **Manual** | `pnpm --filter @mymemory/shared build` (use from repo root if Metro fails to resolve shared) |
| **CI / EAS** | Workflows often run `pnpm --filter @mymemory/shared build` before `eas build` (redundant with `prepare` unless install uses `--ignore-scripts`) |

The explicit CI step is **optional** if installs always run lifecycle scripts (no `--ignore-scripts`); it is still useful as **documentation** and as a safety net.

## Gitignore

Root `.gitignore` includes **`dist/`** and **`build/`** so generated artifacts are never committed. Rely on `prepare`, Turbo, or workflow steps to create them.

## Turbo `build` task

`turbo.json` declares `build` with `dependsOn: ["^build"]` and `outputs: ["dist/**", ...]` so dependent packages see fresh shared output when you run `pnpm build` from the repo root.

## Metro

`apps/mobile/metro.config.js` does **not** need a custom resolver for shared: once `dist/` exists, resolution follows `package.json` `exports` like any dependency. Monorepo settings (`watchFolders`, `nodeModulesPaths`, `disableHierarchicalLookup`) are for pnpm layout + Uniwind.

## Adding a new subpath

1. Add files under `packages/shared/src/…`
2. Extend `tsconfig` `include` if needed
3. Add an **`exports`** entry with `types`, `import`, and `default` all under **`dist/`**
4. Run **`pnpm --filter @mymemory/shared build`** and update consumers

## Troubleshooting

- **`Module not found: @mymemory/shared`** — run shared build; confirm `dist/` exists after install.
- **Server: no exported member from contracts** — check shared **declaration** re-exports use **`.js`** suffixes; rebuild shared.
- **Stale types in IDE** — restart TS server; confirm workspace depends on `workspace:*` and built `dist`.
